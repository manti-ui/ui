# Color & variants

Manti UI separates fixed color scales from the semantic roles components use.

## Primitive scales

Every primitive is a 12-step scale from [Radix Colors](https://www.radix-ui.com/colors)
(`@radix-ui/colors`), taken verbatim under a plain color name:

| Scale    | Radix scale | Purpose     | Use it for                                             |
| -------- | ----------- | ----------- | ------------------------------------------------------ |
| `gray`   | `slate`     | Neutral UI  | Surfaces, borders, text, and secondary controls        |
| `orange` | `orange`    | Primary     | Main actions, selected states, and the product accent  |
| `green`  | `green`     | Success     | Positive feedback, completed states, and confirmations |
| `blue`   | `blue`      | Information | Informational feedback, notices, and helpful context   |
| `amber`  | `amber`     | Warning     | Caution, attention, and states that need review        |
| `red`    | `red`       | Danger      | Errors, destructive actions, and critical feedback     |

<ColorRamps />

Each step is available as `--manti-{scale}-{step}`, and each one is a
`light-dark()` pair of the Radix light and dark step with the same number:

```css
--manti-orange-9: light-dark(#f76b15, #f76b15);
--manti-gray-1: light-dark(#fcfcfd, #111113);
```

So a step is not a fixed lightness. `gray-1` is the app background in both
schemes: near-white in light, near-black in dark. A step names a job, and the
scheme picks the color. `pnpm gen:tokens` writes these pairs from
`@manti-ui/tokens`. The surface, text, and border roles in `tokens.css` read a
single step and follow `color-scheme` with no `light-dark()` of their own. The
exception is `--manti-overlay`: Radix ships one `blackA` scale for both schemes,
so the scrim picks its step with `light-dark()`, `black-a6` in light and
`black-a8` in dark.

Component CSS should use semantic tokens or variants instead of choosing a step
directly.

## Step contract

These are the Radix step semantics. The mapping comes from `colorScaleRoles` in
`@manti-ui/tokens`, and every scale uses it:

| Step | Source role                  | Purpose                                           |
| ---- | ---------------------------- | ------------------------------------------------- |
| `1`  | `appBackground[0]`           | App background                                    |
| `2`  | `appBackground[1]`           | Subtle background: panels, sidebars, striping     |
| `3`  | `componentBackground.rest`   | Resting component background                      |
| `4`  | `componentBackground.hover`  | Hovered component background                      |
| `5`  | `componentBackground.active` | Active, pressed, or selected component background |
| `6`  | `border.subtle`              | Subtle borders and separators                     |
| `7`  | `border.interactive`         | Interactive borders                               |
| `8`  | `border.strong`              | Strong borders and the variant focus ring         |
| `9`  | `solid.rest`                 | Resting solid fill                                |
| `10` | `solid.hover`                | Hovered solid fill                                |
| `11` | `text.lowContrast`           | Supporting or lower-contrast text                 |
| `12` | `text.highContrast`          | Primary or highest-contrast text                  |

Because a step keeps its job in both schemes, "one step stronger" gains contrast
in light and in dark alike. The interaction ladder is the same everywhere: soft
surfaces go rest `3` → hover `4` → active `5`, and solids go `9` → `10`.

## Where a role moves off the nominal step

The styles build checks every role against a contrast floor. Where a Radix step
misses it, the role moves one step up instead of the step being retuned:

| Role                                 | Step | Why                                                 |
| ------------------------------------ | ---- | --------------------------------------------------- |
| `--manti-focus-ring` (neutral)       | `9`  | Slate `8` misses 3:1 against the page in light      |
| `--manti-warning-text`               | `12` | Amber `11` misses WCAG AA on the surface in light   |
| `--variant-soft-text`, every variant | `12` | Step `11` misses AA on the step `3` soft background |
| `--manti-text-subtle`                | `11` | Step `10` misses AA, so subtle shares muted's step  |

Labels on a solid fill do not read a scale step. They use two fixed inks, the
same in both schemes: `--manti-ink-light` (consumed as `--manti-text-on-accent`)
and `--manti-ink-dark` (consumed as `--manti-text-on-bright`). The generator
measures each variant's solid to set its `--variant-on-solid`. The accent
variants (`primary`, `success`, `info`, `danger`) use the dark ink in both
schemes. The neutral variants (`secondary`, `tertiary`, `outline`) switch ink
per scheme with `light-dark()`: the light ink on the dark `gray-12` solid in
light, the dark ink on the light `gray-12` solid in dark.

The `--variant-*` mappings are:

| Variant                                    | Solid      | Soft                 | Border  | Text      | Ring                 |
| ------------------------------------------ | ---------- | -------------------- | ------- | --------- | -------------------- |
| `primary`, `success`, `info`, and `danger` | `9` → `10` | `3` → `4` → `5`      | `7`     | `11`      | `8`                  |
| `secondary`, `tertiary`, and `outline`     | `gray-12`  | `gray-3` → `4` → `5` | neutral | `gray-12` | `--manti-focus-ring` |

For the accent variants, the pressed solid (`--variant-solid-active`) mixes the
hover step toward `gray-12`, the direction that gains contrast in each scheme.
The neutral variants already rest on `gray-12`, so they ease the other way: the
hover is an even mix of `gray-12` and `gray-11`, and the pressed solid is
`gray-11`.

Input-like controls are the main exception to the colored-border progression.
They use the neutral border at rest and hover, then introduce the variant color
at focus or open.

## Pick another scale

There is no free color and no generated ramp. A theme names Radix scales: one
accent per variant and one gray as the neutral. The catalog of names is
`radixScales` in `@manti-ui/tokens` (25 accents and 6 grays), and each accent
entry names the gray Radix pairs it with.

- Adopt a [theme preset](/guides/themes): each one is a named pair, such as
  `sky` on `slate` or `grass` on `sage`.
- Pick scales by name in [Oklava](/guides/oklava) or the
  [Theme Studio](https://studio.manti.design) and export the CSS.
- Write the override yourself from `radixScales`, as the
  [theming guide](/guides/theming-tokens#pick-a-radix-scale) shows.

The single neutral hue property that used to tint every gray is gone, so there
is no hue to set. To move the neutral, pick another Radix gray.

## Built-in variants

Manti ships seven variant palettes:

- `primary` — orange, highest emphasis;
- `secondary` — neutral soft surface;
- `success` — green feedback;
- `info` — blue feedback;
- `tertiary` — neutral ghost;
- `danger` — red feedback;
- `outline` — neutral bordered treatment.

<VariantGallery />

Individual components may expose a subset. Alert supports `primary`,
`secondary`, `success`, `info`, and `danger`. Badge omits `tertiary`. Button also
adds `link`.

Every variant defines the same roles:

```text
--variant-solid
--variant-solid-hover
--variant-solid-active
--variant-on-solid
--variant-soft-bg
--variant-soft-bg-hover
--variant-soft-bg-active
--variant-soft-text
--variant-border
--variant-text
--variant-ring
```

## Custom variant

Components typed with `MantiVariant` accept custom strings:

```css
[data-variant='brand'] {
  --variant-solid: var(--manti-blue-9);
  --variant-solid-hover: var(--manti-blue-10);
  --variant-solid-active: color-mix(
    in oklab,
    var(--manti-blue-10) 88%,
    var(--manti-gray-12)
  );
  --variant-on-solid: var(--manti-text-on-bright);
  --variant-soft-bg: var(--manti-blue-3);
  --variant-soft-bg-hover: var(--manti-blue-4);
  --variant-soft-bg-active: var(--manti-blue-5);
  --variant-soft-text: var(--manti-blue-12);
  --variant-border: var(--manti-blue-7);
  --variant-text: var(--manti-blue-11);
  --variant-ring: var(--manti-blue-8);
}
```

```tsx
<Button variant="brand">Save</Button>
```

## Contributor checks

Use semantic roles in component CSS, keep foregrounds explicit, and verify both
themes:

```bash
pnpm check:color-scale
pnpm --filter @manti-ui/styles check:contrast
pnpm --filter @manti-ui/styles build
```
