# Color & variants

Manti UI's palette comes from the mantı kitchen — warm, edible references turned
into perceptually-smooth color. Color is split in two: fixed **primitive ramps**
you rarely touch directly, and **variants** — the single color-and-emphasis
dimension that components actually read.

## The OKLCH primitive ramps

Six ramps run from `1` (lightest) to `12` (darkest), each authored in **OKLCH**
so steps are perceptually even — equal jumps in lightness look equal to the eye,
and hues stay stable across the scale. These values are fixed and identical in
light and dark. The stops are a plain index rather than Tailwind-style `50…950`
weights; if you use the Tailwind bridge, the familiar `bg-orange-500` utility
names still work and map onto these stops.

Twelve steps because that is what the roles need: `1`–`2` page and panel
backgrounds, `3`–`5` component backgrounds, `6`–`8` borders and separators,
`9`–`10` the solid fills, `11`–`12` text.

| Ramp     | Role      | Reference    |
| -------- | --------- | ------------ |
| `gray`   | neutral   | warm neutral |
| `orange` | primary   | warm orange  |
| `red`    | danger    | hot red      |
| `green`  | —         | fresh green  |
| `amber`  | secondary | golden amber |
| `blue`   | —         | calm blue    |

Each step is a `--manti-{ramp}-{step}` custom property — `--manti-orange-7`,
`--manti-gray-12`, and so on.

Per the [design signature](/foundations/design-signature), these ramps never
appear as gradients or a brand accent. They feed the variants below, and the warm
`gray` ramp also backs the cool monochrome surfaces and text.

## The five variants

Variant-driven components — Button, Badge, Alert, Switch, and friends — never
hard-code a hue. They set a `data-variant` and read a small, uniform vocabulary
of `--variant-*` variables. A single `variant` prop carries **both** the hue and
the emphasis. Manti UI ships five built-in variants:

- `primary` — orange solid, the highest-emphasis signature accent
- `secondary` — amber soft, the default for Badge and Alert
- `tertiary` — neutral ghost (text only), the lowest emphasis
- `danger` — red solid, the semantic hue
- `outline` — neutral bordered: a transparent background with a visible border

The first three form an **emphasis ladder** (`primary` → `secondary` →
`tertiary`); `danger` is the one semantic hue and `outline` is a neutral bordered
treatment.

Two things worth knowing about `secondary`. It is chromatic, so the top two rungs
of the ladder both carry color — when you want a genuinely quiet control, reach
for `tertiary` or `outline`, not `secondary`. And it draws on the same `amber`
ramp that reads as caution elsewhere, so an amber badge is not automatically a
warning; use `danger`, or a custom variant, when the meaning has to be
unambiguous.

## How a variant maps to `--variant-*`

Selecting `[data-variant='primary']` swaps in a complete set of role variables
that every variant-driven component consumes the same way:

```
--variant-solid            --variant-soft-bg          --variant-border
--variant-solid-hover      --variant-soft-bg-hover    --variant-text
--variant-solid-active     --variant-soft-text        --variant-ring
--variant-on-solid         --variant-fill             --variant-fill-strong
```

`--variant-fill` (hover) and `--variant-fill-strong` (selected/pressed) are the
variant-colored interactive fills; they derive from `--variant-soft-bg`, so a
custom variant that defines the soft role gets them for free.

Because a component only ever reads `--variant-*` — never a raw ramp step — the
same markup restyles completely when you change its variant:

```tsx
<Button variant="primary">Save</Button>
<Button variant="danger">Delete</Button>
```

The variant values themselves use `light-dark()` to stay theme-aware and
`color-mix()` to derive soft surfaces and hover states from the resolved solid.

## Custom variants

Any string is a valid variant. To add your own, declare a `[data-variant]` block
that defines the full `--variant-*` vocabulary, then pass it:

```css
[data-variant='brand'] {
  --variant-solid: oklch(0.62 0.16 270);
  --variant-solid-hover: oklch(0.58 0.16 270);
  --variant-solid-active: oklch(0.54 0.16 270);
  --variant-on-solid: var(--manti-text-on-accent);
  --variant-soft-bg: oklch(0.62 0.16 270 / 0.16);
  --variant-soft-bg-hover: oklch(0.62 0.16 270 / 0.24);
  --variant-soft-text: oklch(0.72 0.14 270);
  --variant-border: oklch(0.62 0.16 270 / 0.4);
  --variant-text: oklch(0.72 0.14 270);
  --variant-ring: oklch(0.62 0.16 270);
}
```

```tsx
<Badge variant="brand">New</Badge>
```

The built-in variants keep TypeScript autocomplete via `MantiVariant`, while
still accepting any custom string. Continue to [Design tokens](/foundations/tokens)
for the full token contract.
