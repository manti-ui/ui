# Theming with tokens

Use the broadest token that matches the design decision.

Before writing any of this, check whether a [shipped preset](/guides/themes)
already gets you there — adopting one is a single import. Reach for the tokens
below to retune a preset, or to build a theme none of them cover.

Prefer to see it before you write it? The
[Theme Studio](https://studio.manti.design) tunes these same tokens live on a
full product surface, then hands the result back as CSS, as an agent prompt, or
as a shareable link.

| Need                                    | Use             |
| --------------------------------------- | --------------- |
| Swap a palette or the neutral           | A Radix scale   |
| Change a system-wide purpose            | Semantic token  |
| Change color and emphasis               | Variant roles   |
| Make one component intentionally differ | Component token |

## Start with semantic roles

A color role reads one step of a scale. Point it at another step:

```css
:root {
  --manti-bg: var(--manti-gray-2);
  --manti-surface: var(--manti-gray-1);
  --manti-surface-raised: var(--manti-gray-2);
  --manti-border: var(--manti-gray-7);
  --manti-radius-factor: 0.8;
  --manti-duration-base: 180ms;
}
```

Each `--manti-{scale}-{step}` is a `light-dark()` pair of the Radix light and
dark step, so a role that reads a step follows the scheme on its own. Keep each
role on the step whose [Radix job](/foundations/color-and-tones#step-contract)
matches it: backgrounds on `1`–`2`, text on `11`–`12`.

## Use variants for color

Remap a built-in variant on the whole app or within a subtree:

```css
.marketing [data-variant='primary'] {
  --variant-solid: var(--manti-blue-9);
  --variant-solid-hover: var(--manti-blue-10);
  --variant-ring: var(--manti-blue-8);
}
```

See [Color & variants](/foundations/color-and-tones) for the full role list.

## Pick a Radix scale

The stylesheet ships six scales: `gray` (Radix `slate`), `orange`, `green`,
`amber`, `red` and `blue`. Any other color is a Radix scale picked by name.
There is no free color input and no generated ramp, so every theme stays on
steps whose contrast Radix designed. Pick in this order:

1. A [theme preset](/guides/themes), when one of its pairs fits.
2. [Oklava](/guides/oklava) or the [Theme Studio](https://studio.manti.design),
   which pick each variant and the neutral by Radix name and export the CSS.
3. The catalog itself. `radixScales` in `@manti-ui/tokens` holds every scale a
   theme may name, 25 accents and 6 grays, with the light and dark steps of each.

```ts
import { radixScales } from '@manti-ui/tokens';

const { light, dark } = radixScales.teal;
const step = (n: keyof typeof light) => `light-dark(${light[n]}, ${dark[n]})`;

export const tealPrimary = `[data-variant='primary'] {
  --variant-solid: ${step(9)};
  --variant-solid-hover: ${step(10)};
  --variant-soft-bg: ${step(3)};
  --variant-soft-bg-hover: ${step(4)};
  --variant-soft-bg-active: ${step(5)};
  --variant-soft-text: ${step(11)};
  --variant-border: ${step(7)};
  --variant-text: ${step(11)};
  --variant-ring: ${step(8)};
}`;
```

Each accent entry also names `gray`, the neutral Radix pairs it with. To move
the neutral, re-declare `--manti-gray-1` to `--manti-gray-12` from a gray entry,
and `--manti-gray-a1` to `--manti-gray-a12` from its `alpha` scale; every
surface, border and text role follows. The neutral hue property of earlier
versions no longer exists, so a stylesheet that still sets it changes nothing.

## Use component tokens for exceptions

```css
:root {
  --manti-button-radius: var(--manti-radius-full);
}
```

If the same override appears on several components, move it to a semantic token
instead. Do not override private `--_*` variables.

## Retune a size step

`sm | md | lg` is one shared rhythm. A control and the surface it opens resolve
the same `--manti-size-*` channel, so a `sm` Select opens a `sm` listbox and a
`lg` Menu lays out `lg` rows. Popups are portalled, so each adapter re-stamps
`data-size` on its positioner rather than relying on inheritance.

Retune a step once and every control and popup on it follows:

```css
[data-size='sm'] {
  --manti-size-item-padding-y: 0.125rem;
  --manti-size-text: 0.8125rem;
}
```

The channel carries `text`, `text-sub`, `icon`, `control-height`,
`control-padding-x`, `panel-padding`, `panel-gap`, `item-padding-y`,
`item-padding-x`, `item-gap`, `item-radius`, and `cell`. Every component token
above defaults to one of them, so a per-component override still wins.

Continue to [plain CSS](/guides/plain-css) for anatomy selectors or
[Tailwind](/guides/tailwind) for utility integration.
